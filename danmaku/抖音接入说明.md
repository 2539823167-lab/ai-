# 抖音弹幕接入说明

`douyin.py` 的真实接入**已完成**（移植自开源项目 DouyinLiveWebFetcher，AGPL-3.0），
依赖见 [requirements-douyin.txt](../requirements-douyin.txt)，协议文件在 [douyin_protocol/](douyin_protocol/)。

本文档保留协议逆向的**原理说明与更新指南**：抖音协议频繁变更，失效时对照下面各接入点更新。

| 部分 | 状态 | 位置 / 依赖 |

## 1. 协议概览

```
分享链接(短链) --重定向--> live.douyin.com/{web_rid}
        │  GET https://live.douyin.com/        （拿 ttwid Cookie，匿名即可）
        │  GET https://live.douyin.com/{web_rid} （HTML 里正则提取 roomId）
        ▼
wss://webcast*.douyin.com/webcast/im/push/v2/?...&signature=xxx （WebSocket）
        │  收二进制帧 → 需要时回 ACK → 心跳 hb 帧保活
        ▼
二进制帧 → PushFrame → gzip 解压 payload → Response
        → messages 里的 WebcastChatMessage → user.nick_name + content
```

## 2. 三个接入点原理（失效时的更新点）

### 2.1 签名 —— 最难、最不稳定

抖音要求 WebSocket 地址带 `X-Bogus` 签名，由网页端 JS 算法动态生成，**无法从零推导**。
当前实现在 `douyin.py` 的 `_signature(wss)`：按固定顺序拼 WSS 参数 → MD5 →
用 `MiniRacer` 执行 `douyin_protocol/sign.js` 的 `get_sign(md5)` 得到签名。

签名失效时：对照上游仓库 [DouyinLiveWebFetcher](https://github.com/saermart/DouyinLiveWebFetcher)
更新 `douyin_protocol/sign.js`，并核对 `douyin.py` 里的 `_SIGN_PARAMS` 顺序与 `WSS_TEMPLATE`。

### 2.2 WebSocket 连接

用 `websocket-client` 库（`douyin.py` 的 `_connect`）：

```python
self._ws = websocket.WebSocketApp(
    wss, header={"Cookie": f"ttwid={ttwid}", ...},
    on_open=..., on_message=..., on_error=..., on_close=...,
)
self._ws.run_forever()   # 阻塞，断线后返回，由 _run 重连
```

连接建立后另起线程每 5s 发 `PushFrame(payload_type="hb")` 的 PING 帧保活。

### 2.3 protobuf 帧解析

`douyin_protocol/protobuf/douyin.py` 是 **betterproto** 生成的协议类（非 google protobuf）。
解析逻辑在 `douyin.py` 的 `_on_message`：

```python
frame = PushFrame().parse(raw)
resp = Response().parse(gzip.decompress(frame.payload))
for msg in resp.messages_list:
    if msg.method == "WebcastChatMessage":
        chat = ChatMessage().parse(msg.payload)
        # chat.user.nick_name, chat.content
```

协议字段变更时：更新 `douyin_protocol/protobuf/douyin.proto`，再用 betterproto 的
`protoc` 插件重新生成 `douyin.py`（`protoc --python_betterproto_out=... douyin.proto`）。

## 3. 依赖安装

```bash
py -3.10 -m pip install -r requirements-douyin.txt
# 即：requests / websocket-client / py-mini-racer / betterproto==1.2.5
```

- `py-mini-racer` 内置 V8，**无需安装 Node.js**。
- `betterproto` 需锁在 1.x（协议类使用 1.x 的 `.parse()` / `.SerializeToString()` API，2.0 已移除）。
- 这些是**可选依赖**，不影响项目核心（模板 + 模拟弹幕）零依赖运行。

## 4. 接入后的接线（config.json）

```json
"danmaku": { "provider": "douyin", "live_url": "https://live.douyin.com/xxxx" }
```

`main.py` 会按配置装配 `DouyinProvider`，无需改代码；`live_url` 填一个**正在直播**的房间链接。
